# CLI Бързо стартиране (pool-*)

Доставените `chloros-cli` устройства управляват DAQ сензорите чрез семейството команди **`daq pool-*`** — леки HTTP клиенти, които управляват сензора чрез постоянния пул от сензори на Chloros бекенда. Бекендът контролира транспорта, така че графичният интерфейс, CLI и скриптовете SDK споделят един активен идентификатор, вместо да се борят за порта. Всичко, от което се нуждае клиентът, е достъпно чрез `pool-*`: свързване, стрийминг, запис на калибрирани `.daq` файлове и смяна на профили на капаци.

`pool-*` е също така **единственият** DAQ интерфейс в пуснатите версии. `chloros-cli daq --help` изброява подкомандите на `pool-*`, а извикването на подкоманда за директен хардуерен DAQ в пуснатата версия завършва с изрична грешка, посочваща липсващия пакет и пренасочваща ви обратно към `pool-*` — нищо не се проваля без предупреждение. (Командите за директен достъп до хардуера се изпълняват само от изтеглен изходен код на MAPIR; `pip install chloros-sdk` също не ги предоставя.)

***

## Предварителни условия

* **Бекендът Chloros трябва да работи** — командите на `pool-*` са клиенти на HTTP, а не хардуерни драйвери. На Windows стартирайте десктоп приложението Chloros (то стартира бекенда). На Linux/Jetson без монитор активирайте услугата: `sudo systemctl enable --now chloros-backend.service`.
* **Вход в Chloros+ (платен план)**: първо стартирайте `chloros-cli login`. Проверката се извършва от страна на сървъра — без вход командите се провалят с `401 AUTH_REQUIRED`; при безплатния (Iron) план те се провалят с `403 PLAN_UPGRADE_REQUIRED`.
* По подразбиране командите са насочени към `http://127.0.0.1:5000`; семейството `daq pool-*` зачита променливата на средата `CHLOROS_BACKEND_URL`, ако вашият бекенд работи другаде.

***

## Петминутна сесия

```bash
# 1. Connect a sensor into the backend pool (pick the line matching your model)
chloros-cli daq pool-connect                                  # smart-detect any DAQ
chloros-cli daq pool-connect --port COM3                      # DAQ-U on a specific COM port
chloros-cli daq pool-connect --mac AA:BB:CC:DD:EE:FF          # DAQ-M by BLE MAC
chloros-cli daq pool-connect --eth-host daq-e-def330.local    # DAQ-E by hostname (reliable)

# 2. List the pool — this shows the sensor_id used by every command below
chloros-cli daq pool-list

# 3. Read the most recent calibrated spectrum frame (add --json for scripting)
chloros-cli daq pool-latest --sensor-id daq-e-def330 --json

# 4. Record a calibrated .daq file for 60 seconds
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 60 \
  --device-name "field-A"

# 5. Release the sensor when done
chloros-cli daq pool-disconnect --sensor-id daq-e-def330
```

***

## `pool-connect` — отваряне на сензор в пула

| Вариант | Значение |
| --- | --- |
| `daq pool-connect` | Интелигентно откриване: намиране на всеки DAQ на тази машина. |
| `daq pool-connect --port PORT` | DAQ-U на конкретен сериен порт (например `COM3`, `/dev/ttyUSB0`). |
| `daq pool-connect --ble` | DAQ-M през BLE, автоматично сканиране на MAC адреса. |
| `daq pool-connect --mac MAC` | DAQ-M на известен BLE MAC (означава `--ble`). |
| `daq pool-connect --eth-host HOST` | DAQ-E при известно име на хост или IP — **надеждният път**. |
| `daq pool-connect --eth` | DAQ-E с автоматично откриване (mDNS, с резервен вариант ARP). Вижте предупреждението по-долу. |

Флагове за настройка, всички са опционални:

| Флаг | Значение |
| --- | --- |
| `--integration-time MS` / `-t MS` | Ръчно зададено време за интегриране в милисекунди. |
| `--frame-avg N` / `-f N` | Средно число кадри за всеки отчетен спектър. |
| `--no-ae` | Деактивиране на автоматичната експозиция (AE е включена по подразбиране). |
| `--no-stream` | Свързване без стартиране на потока (възобновяване по-късно с `pool-stream --start`). |
| `--cap-id CAP` | Профил за корекция на капацитета; по подразбиране за бекенда е `sunshine_cosine`. Вижте [`pool-set-cap`](#pool-set-cap-declare-the-fitted-cap). |

{% hint style="warning" %}
**Предупреждение относно автоматичното откриване на `--eth`.** На хост с няколко мрежови интерфейса (повече от един активен мрежов интерфейс) *първият* `pool-connect --eth` след стартиране може да не върне резултат, дори ако сензорът е в изправно състояние — търсенето може да пропусне интерфейса на сензора, докато ARP кешът е празен. Ако `--eth` не открие нищо, опитайте отново или пропуснете изцяло откриването с `--eth-host <ip-or-hostname>`, което е надеждният подход при машини с няколко мрежови интерфейса. Името на хоста на DAQ-E е `daq-e-<id>.local` (например `daq-e-def330.local`); обикновеният му IP адрес също работи.
{% endhint %}

## `pool-list` — вижте какво е свързано

Показва всеки сензор в пула на бекенда, включително `sensor_id`, който е необходим за всички останали команди:

| Модел | Формат на `sensor_id` | Пример |
| --- | --- | --- |
| DAQ-U / DAQ-M | 5-октетен с тирета | `CB-7C-A8-2E-5F` |
| DAQ-E | `daq-e-<6 hex digits>` | `daq-e-def330` |

## `pool-latest` — четене на спектрални рамки

```bash
chloros-cli daq pool-latest --sensor-id daq-e-def330 --recent 10 --json
```

Връща най-новия кадър или най-новите `--recent N` кадри; `--json` генерира машинно четим изход за скриптове. Кадрите представляват радиометрично калибрирана спектрална интензивност на излъчването (W/m²/nm) върху решетка от 135 точки в диапазона 340–1010 nm, като профилът на капачката на сензора вече е приложен. За количествени стойности на интензитета на излъчването изчислете средната стойност от поне 15 секунди кадри — това е характеристика на уреда, а не дефект.

## `pool-stream` — пауза или възобновяване на стрийминга

```bash
chloros-cli daq pool-stream --sensor-id daq-e-def330 --stop    # pause
chloros-cli daq pool-stream --sensor-id daq-e-def330 --start   # resume
```

## `pool-record` — записване на файл `.daq`

```bash
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
  --output ~/Documents/spectra --device-name "rooftop-A"
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

| Флаг | По подразбиране | Значение |
| --- | --- | --- |
| `--duration SEC` / `-d SEC` | `0` | Продължителност на записването в секунди; `0` означава да се изпълнява, докато не издадете `--stop`. |
| `--output DIR` / `-o DIR` | `~/Documents/DAQ Live View/` | Изходна директория, определяна **на машината, на която се изпълнява бекендът**. |
| `--device-name NAME` | — | Етикет, съхранен заедно със записването. |
| `--stop` | — | Спира текущо записване. |

{% hint style="info" %}
Записът се извършва в бекенда, така че файлът `.daq` се записва във файловата система на **машината с бекенда** — по подразбиране в `~/Documents/DAQ Live View/` там, а не непременно там, където сте стартирали CLI. Имената на файловете включват идентификатора на сензора и времева марка.
{% endhint %}

## `pool-set-cap` — деклариране на монтирания капак

```bash
chloros-cli daq pool-set-cap --sensor-id daq-e-def330 --cap-id sunshine_cosine
```

Идентификаторът на капачката избира фабрично измерения коригиращ профил, прилаган към всеки спектър, и той **трябва да съвпада с капачката, физически монтирана на сензора** — нито сензорът, нито софтуерът могат сами да открият капачката, а изборът се записва във всеки файл `.daq`. По подразбиране навсякъде се използва `sunshine_cosine` (всеки DAQ се доставя с инсталиран капак „Sunshine“ за косинусна корекция, с ~12× затихване по проект — недекларирана смяна на капака води до неправилна корекция на спектрите приблизително с този коефициент).

| `--cap-id` | Наличен за |
| --- | --- |
| `sunshine_cosine` (по подразбиране) | DAQ-U, DAQ-M, DAQ-E |
| `fov_15`, `fov_45`, `fov_90` | DAQ-U, DAQ-E |
| `fov_30`, `fov_60` | само DAQ-U |
| `none` | само DAQ-E — виж бележката |

Идентификатор на капачката, който не е от комплекта на сензора, се отхвърля при свързване с ясна грешка. `none` (DAQ-E) означава, че капачката е физически премахната — все още се прилага фабричен геометричен профил за вдлъбнатия стъклен дифузьор на DAQ-E, така че това не е „no-op“, а DAQ-E без капачка е конфигурация за лабораторни условия, а не поддържана конфигурация за работа на място. (Голият DAQ-U е напълно гол и изобщо не се нуждае от профил за корекция; DAQ-M се използва със своя капак „Sunshine“.)

## `pool-disconnect` — освобождаване на сензори

```bash
chloros-cli daq pool-disconnect --sensor-id daq-e-def330   # one sensor
chloros-cli daq pool-disconnect --all                      # everything in the pool
```

## Обобщение на командите

| Команда | Цел |
| --- | --- |
| `daq pool-connect [--port P \| --ble \| --mac M \| --eth \| --eth-host H] [-t MS] [-f N] [--no-ae] [--no-stream] [--cap-id CAP]` | Отваряне на сензор в пула на бекенда. |
| `daq pool-list` | Показване на всеки сензор в пула заедно с неговия `sensor_id`. |
| `daq pool-latest --sensor-id ID [--recent N] [--json]` | Последните N калибрирани спектрални кадри. |
| `daq pool-stream --sensor-id ID [--start \| --stop]` | Възобновяване / пауза на стрийминга. |
| `daq pool-record --sensor-id ID [-d SEC] [-o DIR] [--device-name NAME] [--stop]` | Стартиране / спиране на запис на `.daq` (от страна на бекенда). |
| `daq pool-set-cap --sensor-id ID --cap-id CAP` | Смяна на профила за корекция на капацитета по време на изпълнение. |
| `daq pool-disconnect --sensor-id ID [--all]` | Освобождаване на един сензор или на всички. |

## Отстраняване на проблеми при първото свързване на DAQ-E

1. DAQ-E няма LED индикатор за състоянието — проверете дали има захранване чрез индикатора за PoE/връзка на комутатора или порта на инжектора и изчакайте няколко секунди след включването, за да се стартира устройството и да се присъедини към мрежата.
2. Сървърът трябва да се намира в **същия домейн за разпространение** като сензора — mDNS не преминава през рутери.
3. На Windows при първото стартиране приемете подканата на защитната стена Defender (mDNS UDP 5353, данни от DAQ-E UDP 5002, PTP UDP 319/320).
4. Все още няма отговор от `--eth`? Използвайте `--eth-host` с името на хоста на устройството (`daq-e-<id>.local`) или IP адреса — това е надеждният начин, особено при хостове с няколко IP адреса.
