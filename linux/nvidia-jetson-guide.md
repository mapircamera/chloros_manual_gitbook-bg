# Ръководство за NVIDIA Jetson

Chloros на NVIDIA Jetson позволява мултиспектрална обработка на изображения в периферните устройства — на място, на безпилотни летателни апарати (UAV), и в отдалечени инсталации. Chloros 1.2.0 разпознава вашия модел Jetson при стартиране и оптимизира стратегията си за обработка според открития хардуер. **Не се изисква ръчна настройка.**

***

## Поддържани модели Jetson

| Модел                | RAM            | Стратегия за обработка                                     | Препоръчителна употреба                                          |
| -------------------- | -------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| **Jetson AGX Orin**  | 32–64 GB споделена | `GPU_PARALLEL` (2 работника)                              | Максимална производителност, големи масиви от данни                      |
| **Jetson Orin NX**   | 8–16 GB споделена | `GPU_PARALLEL` (2 работника, 16 GB) / `GPU_SINGLE` (8 GB)   | Основна препоръка за внедряване във въздуха и на терен |
| **Jetson Orin Nano** | 8 GB споделена     | `GPU_SINGLE` (1 работник, последователен)                     | Изчислителни решения от входно ниво за крайни устройства                                 |

{% hint style="info" %}
Пакетът Linux arm64 изисква **JetPack 6**, който е наличен за семейството Jetson Orin. По-старите модели (Nano, TX2, Xavier NX) не могат да изпълняват JetPack 6 и не се поддържат от настоящия пакет.
{% endhint %}

***

## Изисквания

* **JetPack 6.x** (препоръчва се най-новата версия)
* **NVIDIA CUDA** (включена в JetPack)
* **Платен план Chloros+** — ниво „Copper“ или по-високо (задължително за достъп до всички CLI/SDK; налага се от страна на сървъра)

## Инсталиране

```bash
# Install the JetPack 6 .deb package
sudo dpkg -i chloros_1.2.0_arm64_jp6.deb
sudo apt-get install -f

# Verify installation
chloros-cli --version    # prints "Chloros CLI 1.2.0"

# Install Python SDK (optional) — the bundled wheel always matches this build
pip install --user /usr/lib/chloros/sdk/chloros_sdk-*.whl

# Run system diagnostics
chloros-cli selftest
```

За обща информация относно инсталирането на Linux, местоположението на файловете и отстраняването на проблеми вижте [Инсталиране на Linux](linux-installation.md).

{% hint style="info" %}
**Поставете директорията за разпаковане на бързо хранилище.** Компилираните бинарни файлове се разпаковат сами във временна директория при всяко стартиране — което е изключително бавно от SD карта. Chloros използва `/mnt/ssd/tmp` автоматично, когато той съществува; в противен случай задайте `TMPDIR` към пътека на вашия NVMe (`export TMPDIR=/mnt/nvme/tmp`).
{% endhint %}

## Динамична адаптация на изчислителната мощност на Jetson

### Как работи

При стартиране Chloros профилира вашата система:

1. **Разпознава модела на Jetson** чрез `/proc/device-tree/model`
2. **Прочита наличната споделена памет на GPU/CPU** (Jetson използва унифицирана памет)
3. **Избира стратегия за обработка** (`GPU_PARALLEL`, `GPU_SINGLE` или `CPU_PARALLEL`)
4. **Настройва броя на работните процеси, типа на конвейера и разпределението на паметта** автоматично

Решението се определя от **общата споделена RAM**, а не от името на модела:

* **При общо RAM под 12 GB**(всички Jetson с 8 GB): `GPU_SINGLE` с**1 работник — целенасочена последователна обработка**. Паметта е недостатъчна за едновременна работа на работници, затова изображенията се обработват едно по едно. На Jetson с**8 GB или по-малко**, нишка 3 изцяло пропуска пула от работници и изпълнява работата си за всяко изображение в рамките на процеса.
* **12 GB или повече**(Orin NX 16 GB, AGX Orin): унифицираната памет отговаря на изискванията за `GPU_PARALLEL`, но броят на работниците е**ограничен до 2 на Jetson** — GPU, RAM паметта на работните процеси и CUDA контекстите за всеки работник черпят от един и същ споделен пул, така че повече работници рискуват грешки поради липса на памет.

Можете да преопределите автоматичния избор с променливата на средата `CHLOROS_STRATEGY` — вижте [Динамична адаптация на изчислителната мощност](../processing-architecture/dynamic-compute-adaptation.md#manual-strategy-override).

### Поведение за всеки модел

| Модел на Jetson                | Стратегия       | Работни процеси | Изпълнение                                      |
| --------------------------- | -------------- | ------- | ---------------------------------------------- |
| **Jetson Orin Nano 8GB**    | `GPU_SINGLE`   | 1       | Последователен цикъл в рамките на процеса (`tiled_gpu` при недостиг на памет) |
| **Jetson Orin NX 8GB**      | `GPU_SINGLE`   | 1       | Последователна циклична верига в рамките на процеса                     |
| **Jetson Orin NX 16GB**     | `GPU_PARALLEL` | 2       | Едновременни работни процеси, `fused_gpu` път  |
| **Jetson AGX Orin 32–64 GB** | `GPU_PARALLEL` | 2       | Едновременни работни процеси, `fused_gpu` път  |

Основната разлика между платформите е **паметта**. Jetson с 8 GB трябва да обработва изображенията едно по едно, като използва ефективен от гледна точка на паметта подход с разделяне на плочки при висока натовареност, докато Orin с 16 GB+ може да обработва 2 изображения едновременно чрез GPU, използвайки консолидиран конвейер с по-висока пропускателна способност.

### Бюджет на GPU за всеки модел

Всеки модел Jetson разполага и с хардуерен профил, който ограничава колко от споделения пул може да заеме обработката и мащабира размера на партидите:

| Модел | Максимален бюджет на GPU | Множител на размера на партидата | Запазено за системата/дисплея |
| --- | --- | --- | --- |
| **Jetson Orin Nano** | 70% | ×0,8 | 2,0 GB |
| **Jetson Orin NX** | 75% | ×1,0 | 3,0 GB |
| **Jetson AGX Orin** | 80% | ×1,5 | 4,0 GB |

Засечената RAM памет коригира профила: при Jetson, отчитащ **16 GB или повече**, мултипликаторът на партидата се увеличава с ×1,2. Базовият размер на партидата преди мултипликаторите е 8 изображения.

За пълна справка относно адаптацията на изчислителната мощност вижте [Динамична адаптация на изчислителната мощност](../processing-architecture/dynamic-compute-adaptation.md).

## Ограничение на честотата на GPU за Texture Aware на Nano и Orin Nano

Дебайерирането с Texture Aware изпълнява инференция на невронна мрежа на GPU, което може да предизвика **предупреждения за претоварване по ток**при моделите Jetson с ниска консумация на енергия (клас 10–15 W) при пълна тактова честота на GPU. Преди обработката с Texture Aware на**Jetson Nano или Orin Nano**, Chloros проверява максималната честота на GPU и я ограничава до**510 MHz** (510000000), ако в момента тя е по-висока:

* Ако CLI може да запише в sysfs възела за честотата на графичния процесор, ограничението се **прилага автоматично** и се извежда потвърждение.
* Ако не може (изисква root права), CLI извежда точната команда `sudo` за ръчно прилагане на ограничението, изчаква малко, за да можете да я прочетете, след което продължава — обработката все още тече, но може да се показват предупреждения за претоварване.

За да приложите ограничението сами преди обработката:

```bash
echo 510000000 | sudo tee /sys/devices/platform/bus@0/17000000.gpu/devfreq/17000000.gpu/max_freq
```

Моделите с по-висока мощност (Orin NX 25W, AGX Orin 60W) работят на пълна скорост на GPU; не се прилага ограничение. Стандартният дебайер никога не задейства ограничението при нито един модел.

{% hint style="info" %}
**Texture Aware на Jetson винаги обработва по едно изображение наведнъж.** Всеки работник би имал нужда от собствен CUDA контекст (~1 GB), както и от собствено копие на модела за отстраняване на шума, което обединената памет не може да си позволи — затова на Jetson пътят Texture Aware е фиксиран към един-единствен работник с сериализиран достъп до графичния процесор. Очаквайте „Texture Aware“ да бъде значително по-бавен от „Standard“ на всеки Jetson.
{% endhint %}

## Управление на температурата

Устройствата Jetson имат ограничен термичен резерв, особено при затворени или въздушни инсталации. Chloros следи температурата на SoC и автоматично регулира размера на партидите:

| Температура         | Действие                                            |
| ------------------- | ------------------------------------------------- |
| **&lt; 70 °C**          | Нормална работа — пълна скорост на обработка          |
| **70 °C** (Предупреждение)  | Размерът на партидите постепенно намалява (от 100 % до 50 % при температури между 70 °C и 80 °C) |
| **80 °C** (Критично) | Агресивно ограничаване (от 50% до 0% между 80°C и 90°C) |
| **90°C** (Изключване) | Пълно спиране на обработката от GPU — необходимо охлаждане |

{% hint style="warning" %}
**Осигурете адекватна вентилация и отвод на топлината** за продължителна обработка, особено в затворени полеви корпуси или въздушни системи. Термичното ограничаване ще намали производителността на обработката, за да защити хардуера.
{% endhint %}

## Управление на паметта

Устройствата Jetson използват **унифицирана памет** — графичният процесор (GPU) и централният процесор (CPU) споделят една и съща физическа RAM. Посочената VRAM (например ~15,3 GB при Orin NX 16 GB) не е специално предназначена памет за графичния процесор; това е същата RAM, която използват операционната система и всички останали процеси.

### Предупреждение и препоръки относно суапа

Преди обработката на Jetson, CLI преброява RAW изображенията във вашата папка с входни данни (`.tif`, `.tiff`, `.raw`, `.dng` — JPG прегледите не се броят), изчислява максималния обем памет, необходим за изпълнението, и **предупреждава преди стартиране**, ако RAM + swap вероятно са недостатъчни. Предупреждението е озаглавено `LOW MEMORY WARNING - Jetson Detected`, извежда броя на изображенията, RAM, текущия swap, и очакваната максимална стойност, след което дава точните команди `fallocate` / `chmod` / `mkswap` / `swapon`, съобразени с размера на вашия проект (никога по-малък от 8 GB). Програмата прави пауза от няколко секунди, за да не се изгуби съобщението при превъртане назад, след което обработката продължава.**Оценки за паметта, използвани от предупреждението:**

| Режим на дебайериране | Базов | На изображение |
| --- | --- | --- |
| Стандартен | ~1,5 GB | ~10 MB |
| С отчитане на текстурите | ~2,5 GB (модел + Python време на изпълнение) | ~15 MB |

Предупреждението се задейства, когато прогнозираният пик надвиши RAM + суап минус 1 GB резерв за безопасност, като се отчита само суап, **подкрепен с файлове** — конфигурация, използваща само zram, все пак ще бъде маркирана.

За да добавите swap ръчно (пример: 8 GB):



<!-- SCREENSHOT-NEEDED: Terminal on a Jetson Orin (SSH session) showing the full "LOW MEMORY WARNING - Jetson Detected" block printed by `chloros-cli process` on a large folder: the image count and debayer mode line, RAM / current swap / estimated peak figures, and the fallocate/chmod/mkswap/swapon command block it recommends -->

```bash
# Check current memory and swap
free -h

# Create a swap file
sudo fallocate -l 8G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Make persistent across reboots
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```### Обработка на OOM (Out of Memory)

По време на обработката Chloros следи паметта на GPU и плавно намалява производителността, вместо да се срине:

1. Когато използването на паметта на GPU надвиши **85%**, размерите на партидите се намаляват превантивно
2. Ако все пак възникне събитие за изчерпване на паметта, размерът на партидата се **намалява наполовина** и се намалява отново наполовина при всяко следващо OOM; всяка следваща успешна партида отменя това ограничение с една стъпка назад
3. При продължително натоварване конвейерът преминава от `fused_gpu` към по-ефективния по отношение на паметта `tiled_gpu` и, като последна мярка, към обработка от CPU

## Приложение на място

### Съображения относно консумацията на енергия

| Модел Jetson     | Типична консумация на енергия | Забележки                   |
| ---------------- | ------------------ | ----------------------- |
| Jetson Orin Nano | 7–15 W              | DC конектор          |
| Jetson Orin NX   | 10–25 W             | DC конектор          |
| Jetson AGX Orin  | 15–60 W             | USB-C PD или DC конектор |

Планирайте енергийния си бюджет за продължителна обработка — пиковото потребление на енергия се наблюдава по време на Thread 3 (Обработка), който натоварва силно графичния процесор (GPU).

### Препоръки за съхранение

* **NVMe SSD** се препоръчва силно за arm64 приложения
* SD картите са твърде бавни за обработка — използвайте ги само като носители за стартиране
* Предвидете 2–3 пъти по-голям обем от размера на необработените изображения за обработените резултати

### Работа без монитор чрез SSH

Chloros CLI е идеален за инсталации на Jetson без монитор:

```bash
# SSH into the Jetson
ssh user@jetson-hostname

# Process a dataset
chloros-cli process /data/datasets/flight001 --format "TIFF (32-bit, Percent)"

# Monitor export progress
chloros-cli export-status
```

### Постоянно активен бекенд за синхронизация на времето с LATTICE / DAQ-E

Ако вашият Jetson управлява камери LATTICE или светлинни сензори DAQ-E без монитор, активирайте бекенд услугата systemd, за да работи PTP grandmaster непрекъснато (услугата е инсталирана, но по подразбиране не е активирана):

```bash
sudo systemctl enable --now chloros-backend.service
chloros-cli time-sync status
```

Вижте [Инсталация на Linux](linux-installation.md#always-on-ptp-for-headless-hosts) за подробности, включително как пакетът позволява PTP портове 319/320 да бъдат обвързвани без права на root.

### Автоматизирана обработка с systemd

Създайте услуга в systemd за автоматизирана обработка:

```ini
# /etc/systemd/system/chloros-process.service
[Unit]
Description=Chloros Automated Processing
After=network.target

[Service]
Type=oneshot
User=chloros
ExecStart=/usr/bin/chloros-cli process /data/incoming --output /data/processed
StandardOutput=append:/var/log/chloros-process.log
StandardError=append:/var/log/chloros-process.log

[Install]
WantedBy=multi-user.target
```

`chloros-cli process` излиза с ненулева стойност, когато изпълнение, което е поискало продукти, не записва изображения, така че състоянието на грешка в systemd е значимо за мониторинг.

Комбинирайте с таймер на systemd за планирана обработка:

```ini
# /etc/systemd/system/chloros-process.timer
[Unit]
Description=Run Chloros Processing Every Hour

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl enable chloros-process.timer
sudo systemctl start chloros-process.timer
```

## Примери за работни потоци

### Основна обработка с Jetson

```bash
#!/bin/bash
# Process a drone flight dataset on Jetson
chloros-cli process /data/flights/flight_042 \
    --output /data/processed/flight_042 \
    --format "TIFF (32-bit, Percent)" \
    --indices NDVI NDRE GNDVI
```

### Python и SDK на Jetson

```python
from chloros_sdk import ChlorosLocal

with ChlorosLocal() as chloros:
    chloros.create_project("field_survey_042")
    chloros.import_images("/data/flights/flight_042")
    chloros.configure(
        indices=["NDVI", "NDRE", "GNDVI"],
        export_format="TIFF (32-bit, Percent)",
        reflectance_calibration=True
    )
    chloros.process(mode="parallel")

print("Processing complete!")
```

### Пакетна обработка на множество полети

```bash
#!/bin/bash
# Process all flight datasets in a directory
for flight in /data/flights/*/; do
    name=$(basename "$flight")
    echo "Processing $name..."
    chloros-cli process "$flight" \
        --output "/data/processed/$name" \
        --format "TIFF (32-bit, Percent)" \
        --indices NDVI NDRE
    echo "Completed $name"
done
```

## Препоръчителни системи Jetson за използване на терен

За внедряване на терен и във въздуха, обмислете следните варианти на носещи платки Jetson Orin NX 16GB:

* **Въздушни/дронове**: Системи с вибрационна устойчивост (MIL-STD), леки (под 300 g), с пасивно охлаждане
* **Устойчиви за полеви условия**: Водоустойчиви корпуси IP67/IP69K с възможност за свързване на PoE GigE камера
* **Минимални/икономични**: Комплекти за разработчици с допълнителни корпуси

Свържете се с [MAPIR Поддръжка](https://www.mapir.camera/community/contact) за конкретни препоръки относно хардуера, подходящ за вашия сценарий на внедряване.
